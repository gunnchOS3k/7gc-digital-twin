# Prospective follow-up specification — not executed or registered

This document is an author-review proposal, created after the existing results; it is not the frozen historical protocol. Approval, dates, sample size and collection plan remain pending. No new evidence is claimed.

1. Choose named cache/lesson, local editing, coding and transaction tasks; define correctness, deadline, data freshness and required credentials independently of bearer state. Keep unsupported tasks rather than substituting a task after failure.
2. Build a balanced task × device capability × bearer-state corpus including connected application failure, true degraded/transition states and offline success/failure. Calibration and validation splits must be separate.
3. Instrument task outcomes and resource use under controlled loss/congestion/restoration. Record clock/units, queue load, memory/compute, calibrated terminal power and permission/provenance information. Human utility assessment, if proposed, needs an appropriate consent/ethics plan before collection.
4. Freeze an explicitly prospective protocol, source revision, primary endpoints, independent units, assumptions, randomization and sample-size justification before comparison. Evaluate service classification against independent outcomes, not the classifier's own stored labels.
5. Compare executed fixed/cloud/local/fallback policies on the same traces and feasible action set; account for consumed observations, switch costs and compute limits. Label any future-information reference separately. Include harmful cases and model/threshold sensitivity without retuning on held-out outcomes.
6. Seek a separate human reconstruction and external validation. Do not extend the historical 30-seed protocol in place or use extra synthetic seeds as a substitute for physical validity.
